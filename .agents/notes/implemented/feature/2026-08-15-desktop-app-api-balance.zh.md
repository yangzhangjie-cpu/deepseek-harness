# Agent Note: 独立桌面应用与 API 余额界面

Status: implemented

[English](2026-08-15-desktop-app-api-balance.md) | 中文

## 问题

DeepSeek Harness 原本以命令行启动的网页应用形式分发。桌面用户需要一个无需外部运行时或终端、保持网页界面一致的独立应用，并且能够查看 DeepSeek API 余额，同时不把 API 密钥暴露给浏览器代码。

## 决策

仓库在 `desktop/` 中提供 macOS 桌面壳。它内置压缩后的 Node.js 运行时，首次启动时将运行时展开到应用的私有支持目录，在仅限回环地址的随机端口上启动生产版 Harness 服务，并通过 `WKWebView` 显示现有网页客户端。原创高清图标以 PNG 源图和 macOS ICNS 资产保存。`desktop/build-app.sh` 会复制图标、构建、裁剪、签名，并拒绝超过 200 MiB 的应用。

桌面壳提供标准 macOS“编辑”菜单，使 WebKit 的文本输入框和安全输入框能够响应复制、粘贴快捷键。当尚无工作区时，document-end 桥接会接管原本无响应的添加／选择工作区与新建会话控件并打开 `NSOpenPanel`；用户选中的目录通过仅限回环地址的 `workspace.create` API 注册，随后未经改写的网页客户端重新加载并进入正常工作区流程。该桥接只处理空状态初始化，不替代已有工作区的导航逻辑。

WebView 将顶部 32 像素的中间区域保留为原生拖动区，因为全尺寸 WebKit 内容会占用透明标题栏原本可拖动的背景。左侧导航和右侧设置控件位于拖动区之外；双击仍保留标准 macOS 窗口缩放行为。

session-log-export 插件负责在现有导出控件旁显示余额控件，并在设置中提供独立更新操作。浏览器端控制器会立即刷新，并每 30 秒刷新一次。它向同源 `/api/desktop.balance` 发出请求；宿主路由通过凭据服务解析 `DEEPSEEK_API_KEY`，再调用 DeepSeek 余额 API。该路由只返回余额数据或标准化错误，绝不返回凭据。

桌面壳还会向网页客户端公开内置版本和软件更新消息通道。仅桌面版显示的“通用设置”行会请求原生壳检查官方 GitHub Releases API。发现新版本时，它会把匹配 macOS Apple Silicon 的 ZIP 或 DMG 下载到用户的“下载”目录并在 Finder 中定位；发布版本没有匹配资产时则打开其官方发布页。普通浏览器版本不会注册该设置行。

## 考虑过的替代方案

- **用原生视图重写界面**——会重复实现现有网页产品，并使视觉和行为一致性难以维护。
- **由浏览器代码直接调用 DeepSeek API**——必须把密钥传入渲染进程，扩大凭据暴露边界。
- **依赖系统安装的 Node.js**——可以减小包体，但无法满足没有开发工具时直接打开的要求。
- **内置未压缩运行时**——首次启动更快，但会让交付物更接近 200 MiB 上限，降低后续增长空间。
- **在应用运行时自动覆盖安装更新**——安装在受保护位置的应用需要特权或单独签名的辅助程序；下载并定位官方安装包可让替换操作保持明确。

## 后果

桌面应用会自动沿用网页界面，用户可直接打开 app 包，凭据始终留在宿主进程。首次启动会进行一次私有运行时展开。更新需要官方发布资产，下载后由用户明确替换应用。当前产物面向 macOS Apple Silicon；其他操作系统需要各自的平台壳和运行时。构建验证覆盖网页与库构建、应用体积门禁、代码签名校验、直接启动、回环服务启动、余额接口缺少密钥时的行为、更新设置行注册与原生更新检查反馈、原生工作区选择、安全输入框粘贴且不保存、完成一次 DeepSeek 对话，以及随后新建空白对话。
